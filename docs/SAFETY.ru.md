# DiskShell 0.5.7 — безопасность и ответственность оператора

DiskShell предназначен для системных администраторов, инженеров хранения и других пользователей, которые понимают последствия операций с накопителями.

Разрушительные операции могут необратимо уничтожить данные. Перед их применением оператор должен понимать различие между:

- физическим диском;
- таблицей разделов GPT/MBR;
- разделом;
- томом;
- файловой системой;
- буквой диска / точкой монтирования;
- свободным и нераспределённым пространством.

Проект поставляется **as-is**. Оператор самостоятельно принимает решение о выполнении операций и несёт ответственность за выбор правильного физического диска, наличие резервных копий и последствия применения. В пределах, допускаемых применимым законодательством, авторы проекта не принимают на себя ответственность за потерю данных, простой или иной ущерб, возникший из-за использования destructive-функций.

Это предупреждение не заменяет резервные копии, change-management и процедуры организации.

## Модель записи в 0.5

`DS_ALLOW_DISK_WRITES=0` больше не означает, что администратор вообще не может работать с выбранным storage-диском.

При этом значении:

- глобальное разрешение записи на любые непротектед диски выключено;
- для конкретного непротектед physical disk можно включить WRITE тумблер из UI;
- разрешение привязано к Number + UniqueId/Serial + Size;
- отдельная typed-confirmation для включения WRITE не требуется;
- таймера авто-блокировки нет;
- WRITE остаётся включённым до ручного выключения или restart backend;
- при смене identity диска разрешение автоматически сбрасывается;
- System / Boot / Application disk включить на запись нельзя.

`DS_ALLOW_DISK_WRITES=1` остаётся глобальным override для лабораторной/автоматизированной среды и не рекомендуется для обычной эксплуатации.

## Перед destructive-операцией

1. Проверь модель, serial, UniqueId и размер.
2. Убедись, что это не system/boot/application disk.
3. Проверь резервную копию.
4. Прочитай план операции.
5. Введи точную confirmation-фразу.
6. После операции повторно проверь разметку и файловую систему.

## Stop / Cancel

Quick Index, Placement Executor, Files Copy/Move и Security Scan имеют cancel/stop.

Stop является cooperative:

- scanner прекращает обход между файловыми операциями;
- cross-volume placement copy проверяет cancel между chunks;
- Microsoft Defender / ClamAV process завершается по запросу;
- уже завершённые атомарные операции не «отматываются» автоматически;
- same-volume placement может быть rollback через journal при соблюдении условий.

## Почему у destructive storage operations нет кнопки Stop

Прерывать процесс между Clear-Disk / Initialize-Disk / New-Partition / Format-Volume опасно: диск может остаться в промежуточном состоянии. Поэтому DiskShell показывает activity indicator, блокирует повторные write-команды и не выдаёт фиктивный процент или небезопасный Stop.

## Remote Commander

SFTP/FTP connection credentials не сохраняются на диск. Remote write-команды подчиняются `DS_ALLOW_FILE_WRITES`. Local F8 использует Recycle Bin; remote F8/Delete не имеет системной корзины и требует явного подтверждения. При cross-endpoint move источник удаляется только после завершённой копии и проверки размера.

Remote preview ограничен размером temporary cache, чтобы случайный F3 не скачивал многогигабайтный образ целиком.
